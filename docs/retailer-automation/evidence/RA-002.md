## Scope and safety boundary

RA-002 adds a local, retailer-neutral contract and deterministic fixture harness.
It does not import or call a production executor, database client or network
module. It is not referenced by a production entry point, workflow, scheduler,
retailer config or application route. It grants no policy authorization and
cannot apply a change.

No SQL, migration, import, approval, apply, workflow dispatch, live feed, live
API, secret, staging write, production write, shadow run or retailer cutover was
used. Existing legacy paths remain active and unchanged.

## Canonical contract v1

The closed runtime schema includes:

- `contract_version: v1`;
- neutral retailer/source references and source type;
- injected run ID, UTC capture time and SHA-256 source fingerprint;
- source record, external product and external variant identities;
- SKU, GTIN, product name, brand, variant and source URL;
- price as a decimal-string-to-integer-minor-unit conversion bounded to
  `0..9007199254740991` plus a three-letter currency code; JavaScript
  floating-point input is rejected;
- canonical UTC timestamps, explicit source-present product-identity rules and
  recursively frozen records;
- availability `IN_STOCK`, `OUT_OF_STOCK`, `UNKNOWN`, `MISSING`, `INVALID` or
  `SOURCE_MISSING`;
- independent `PRESENT`, `UNKNOWN`, `MISSING` and `INVALID` field states plus
  record-level `MISSING_FROM_SOURCE`;
- field provenance, identity evidence, normalization warnings, structured
  validation result/reason codes and deterministic record fingerprint.

`MISSING_FROM_SOURCE` maps to `SOURCE_MISSING`, never to `OUT_OF_STOCK`.

## Taxonomy and authorization separation

The v1 code has independent source state, change classification, execution
state, run outcome, alert level, next action and reason code enumerations. Run
outcomes include `PASS`, `PASS_WITH_REVIEW`, `SKIPPED_EQUIVALENT_ACTIVE`,
`NO_AUTHORIZED_SCOPE`, `BLOCKED_SOURCE`, `BLOCKED_GUARDRAIL` and
`FAILED_SYSTEM`.

Each reason binds stable code, row/retailer/platform scope, category,
terminality, review requirement, blocking scope, alert and next action. No
reason names a retailer.

Detection, safety assessment, policy authorization, manifest approval,
execution and postflight are separate report fields. A `SAFE_CANDIDATE` remains
`NOT_AUTHORIZED`; without an approved policy the run is
`NO_AUTHORIZED_SCOPE`, no apply is attempted and postflight is
`NOT_RUN_ZERO_WRITE`.

## Determinism, zero-write and zero-network evidence

Two replays of `mixed-isolated` with the same fixture and injected clock were
deep-equal and produced:

```json
{
  "same": true,
  "output_fingerprint": "ece182eb3fe160a94d27b5ecd882d7126060ec657f1d775ea5e4b2928bd377f7",
  "write_attempt_count": 0,
  "network_attempt_count": 0,
  "run_outcome": "PASS_WITH_REVIEW",
  "rows": 2
}
```

The default harness exposes no writer or network implementation. Its injected
capability boundary counts and throws `ZERO_WRITE_WRITE_ATTEMPT` or
`ZERO_WRITE_NETWORK_ATTEMPT` on first use; both paths have regression tests.
The runtime and recursive source-import graph test proves the harness does not
load the importer, executor, production role/session module, Supabase,
PostgreSQL, filesystem or Node network modules. It also rejects dynamic
`require`, dynamic `import`, environment access and direct/global `fetch` in the
complete local dependency closure.

## Independent verification — 23 September 2026

Independent verification started from baseline
`74e079ad099e72e2c7dcf84c9f4909c164740f17` and exact remote PR head
`94a543aa628a3c378b7761c90943efbcdbf1c76e`. The reviewer read the approved
architecture and decision pack, reviewed every PR file, exercised negative
cases directly and traced both the loaded runtime graph and recursive static
import closure.

Five bounded RA-002 issues were found and corrected without changing a
production entry point:

1. canonical hashing previously reused an offer-sync artifact helper whose
   transitive source-reader module exposed a dormant `globalThis.fetch`
   fallback; hashing now uses the network-free snapshot canonical hasher and
   the dependency test recursively rejects that class of regression;
2. minor-unit money had no explicit safe upper bound; it now accepts only
   non-negative decimal-string input within `Number.MAX_SAFE_INTEGER` minor
   units;
3. capture timestamps accepted non-canonical offsets and source-present rows
   could omit their product identity; timestamps now canonicalize to UTC and
   the identity rule fails closed with `CANONICAL_SOURCE_INVALID`;
4. availability did not independently encode missing and invalid values; both
   are now explicit and source absence remains `SOURCE_MISSING`, never OOS;
5. the harness diff omitted currency, allowing a cross-currency value with the
   same minor units to appear unchanged; currency drift now requires review.

The review also added a distinct aggregate-guardrail fixture, key-order and
deep-immutability assertions, unsafe-money/date/identity/availability
regressions, currency-drift regression and a recursive dependency-source test.
No new dependency, migration, workflow, scheduler, retailer configuration,
production entry point, approval, executor, database path or live fixture was
added. Zero-write and zero-network counters remained `0`; their injected
attempts failed before any side effect with the two `ZERO_WRITE_*_ATTEMPT`
codes. RA-003 remains `NOT_STARTED`.

The first independent `verify:full` attempt was not counted as a pass: an
unchanged tracked nutrition manifest still had CRLF bytes in the new Windows
worktree, so its existing byte-equality test failed. The worktree copy was
normalized to the exact indexed LF hash, the focused legacy test then passed
3/3, and a complete fresh `verify:full` run passed. No nutrition content or Git
diff changed.
